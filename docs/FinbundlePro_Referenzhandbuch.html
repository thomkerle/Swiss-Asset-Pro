01

Enterprise Systemphilosophie (Zero-Cloud & Offline-First)

Moderne Cloud-FinTechs bergen für anspruchsvolle Privatanleger und Treuhänder fundamentale Risiken: Das Hochladen von Kontosalden, Wertpapierbeständen, IBANs und Steuerbelegen auf fremde Cloud-Server exponiert intime Finanzdaten gegenüber Data-Mining, unangekündigten Plattformabschaltungen und regulatorischen Durchgriffen.

FinBundle PRO setzt dem eine unbestechliche, lokale Desktop- und Web-Architektur entgegen: Sämtliche Berechnungen laufen auf der lokalen CPU/GPU des Endgeräts. Es existiert keine zentrale Nutzerdatenbank. Externe APIs (wie Google Gemini, EODHD oder die Frankfurter EZB-Schnittstelle) werden streng als zustandslose Helferdienste gekapselt[cite: 9, 10]. Zu keinem Zeitpunkt verlassen Vermögenssalden oder historische Transaktionsbeträge das Gerät.

03

Kryptografie & AES-256 Vault-Pipeline

Im Speicher wird das Projekt als konsistenter In-Memory JSON-State gehalten. Beim Sichern greift die kryptografische Pipeline:

// Schlüsselableitung via PBKDF2: Key = PBKDF2(Passphrase = NutzerPIN, Salt = CryptoRandom(16 Bytes), Iterationen = 100'000, Hash = SHA-256) // Verschlüsselung: Ciphertext = AES-256-CBC(Plaintext = JSON_State, Key, IV = CryptoRandom(16 Bytes)) Vault_Container = Deflate_ZIP(Ciphertext + Metadaten_Header)

Dank W3C File System Access API schreibt der Browser die Binärdaten direkt auf die lokale Festplatte des Anwenders. Ein unbefugter Zugriff ohne den PIN ist selbst mit Supercomputern mathematisch ausgeschlossen.

04

Der konstante Fixsternpunkt-Ansatz (Stichtags-Inventur)

Die mathematische Unfehlbarkeit der FinBundle PRO Bilanzierung

Klassische Finanzprogramme berechnen Kontostände rein additiv aus allen jemals erfassten Buchungen. Fehlt eine einzige Quittung aus dem Jahr 2021, weicht der Saldo im Jahr 2026 für immer ab.

⭐ Das Fixsternpunkt-Axiom

Ein Fixsternpunkt (Stichtags-Saldo $B_0$) ist eine unumstößliche Tatsachenfeststellung zu einem definierten Datum $t_0$ (z. B. offizieller Bankauszug per 31. Dezember mit exakt 14'250.00 CHF). Er entkoppelt historische Buchungszeiträume voneinander!

RawValue(t) = B(t_0) + Summe aller Zu- und Abflüsse im Intervall ]t_0, t]

Wird eine Buchung im Jahr 2023 korrigiert, hat dies keinerlei fehlerhafte Auswirkung auf das Jahr 2026, sofern per 31.12.2024 ein Fixsternpunkt gesetzt wurde. Fehlende Belege führen nie wieder zu dauerhaften Asymmetrien.

05

Buchungsfluss & Doppelbuchungs-Integrität

FinBundle PRO unterscheidet strikt zwischen vermögensverändernden Transaktionen und rein internen Liquiditätsverschiebungen[cite: 9]:

  • Einzahlung / Auszahlung: Echter externer Cashflow (Lohn, Miete, Konsum)[cite: 9]. Verändert das Nettovermögen[cite: 9].
  • Umbuchung: Verschiebung zwischen zwei Konten (Girokonto ➔ Sparkonto)[cite: 9]. Der Umbuchungs-Assistent erzeugt automatisch eine verknüpfte Gegenbuchung[cite: 11]. Das Gesamtvermögen bleibt neutral[cite: 9].
  • Wertanpassung: Berichtigung von Buchwerten oder Abbildung von Marktschwankungen ohne Geldfluss[cite: 9, 11].

KI-Buchungsassistent (QuickAgentBar, Gemini API & WriteEngine)

RC5 Enterprise Voice- & Parameter-Extraction Pipeline

In Version RC5 ist der Buchungsassistent tief in die Kopfleiste integriert[cite: 10]. Er verarbeitet Freitext und Audiodiktate in Sekundenschnelle[cite: 10].

Die 4 Phasen der Copilot-Pipeline:

  1. Audio-Erfassung & Transkription: Das Audiosignal wird lokal im Opus-Format aufgenommen und als Base64-Payload an gemini-3.8-flash übergeben[cite: 10]. Die KI liefert den exakt transkribierten Text zurück[cite: 10].
  2. Sichtprüfung im Eingabefeld: Der erkannte Wortlaut landet direkt im Textfeld der QuickAgentBar. Der Anwender sieht Beträge und Namen vor der Ausführung.
  3. Function Calling & Metadaten: Gemini analysiert den Text gegen den Systemkontext (vorhandene Bank- und Kontonamen, erlaubte Kategorien, Händler-Memory)[cite: 10]. Relative Datumsangaben („vorgestern“) werden in ein valides ISO-Datum (YYYY-MM-DD) umgewandelt[cite: 10].
  4. Lokale Ausführung (FinBundleWriteEngine): Die KI führt selbst keine Schreiboperationen durch[cite: 10, 11]. Sie liefert typisierte Parameter an die lokale FinBundleWriteEngine, welche das Zielkonto im Baum auflöst und die Buchung transaktionssicher schreibt[cite: 10, 11].
// Typisiertes Tool-Schema der FinBundleAgentEngine: { "name": "book_transaction", "parameters": { "bankName": "UBS", "accountName": "Hauptkonto", "amount": 23.85, "type": "Auszahlung", "category": "Lebensmittel", "bookingText": "Coop einkauf", "date": "2026-10-08" } }
07

Beleg-Scanner & Clientseitiges PII-Gate (PdfScanner.jsx)

Für Sammelrechnungen und Kontoauszüge verfügt FinBundle PRO über das Modul PdfScanner. Um Datenschutz nach Schweizer revDSG und EU-DSGVO zu garantieren, ist ein mehrstufiges PII-Gate (Personally Identifiable Information) vorgeschaltet:

  • Automatisierte Maskierung: IBANs, Kreditkartennummern, Telefonnummern und Wohnadressen werden clientseitig durch Platzhalter ersetzt.
  • Tokenisierung von Kontonamen: Reale Bezeichnungen werden durch [BANK_1] ersetzt. Nach der KI-Verarbeitung erfolgt die Rückübersetzung lokal über ein Dictionary.
  • Interaktive Review-Box: Bei Verwendung von Cloud-Modellen (Gemini, OpenAI, Claude) kann der Anwender den bereinigten Text in einer Textarea vor dem Absenden manuell anpassen.
  • Lokale Offline-Modelle: Alternativ kann der Scan vollständig offline über lokale Ollama-Modelle (z. B. Qwen 2.5 Coder, Llama 3) abgewickelt werden.
08

Auto-Valuation Engine v2 & Total Return Spikes

Synthetische Bewertungslogik mit Dividenden-Reintegration

Börsengehandelte Titel unterliegen Kursschwankungen und schütten Erträge aus[cite: 9]. Die Auto-Valuation Engine v2 trennt den reinen Buchwert mathematisch vom realen Börsenwert[cite: 9]:

Principal (Investiertes Kapital) = Summe(Käufe) - Summe(Verkäufe) Marktwert = Reale Stückzahl × Letzter Schlusskurs × FX_Rate Unrealisierter Kursgewinn = Marktwert - Principal // Total Return Formel (in Sparkline-Spikes visualisiert): Total_Return_Absolut = Unrealisierter Kursgewinn + Kumulierte_Dividenden Total_Return_Prozent = (Total_Return_Absolut / Principal) × 100%

Am Ex-Dividenden-Tag bricht der optische Aktienkurs um die Ausschüttungshöhe ein. FinBundle PRO kompensiert diesen Knick in den Mini-Sparks vollständig: Jede erfasste Dividende wird mathematisch in die Performancekurve reintegriert.

Mitteilungszentrale & Börsen-Radar (RC4 / RC5)

Automatischer 10-Minuten Takt, Signal-Pulsieren • Keine ungewollten Buchungen

Die Mitteilungszentrale (Slide-Over Drawer) dient als reines Informations-Cockpit[cite: 7]. Sie nimmt keine eigenmächtigen Buchungen vor[cite: 7].

1. Börsen-Radar

Vergleicht hinterlegte Buchungskurse alle 10 Minuten mit den EODHD-Live-Kursen[cite: 9]. Farbige Kacheln zeigen Kursgewinne/Verluste in % und den absoluten Gesamteffekt in CHF.

⚠️ Ab ≥ 5% Abweichung pulsiert die Kachel mit orangem Rand als Handlungsaufforderung (Rebalancing)[cite: 7, 9].
2. Buchungs-Audit

Echtzeit-Protokoll aller Transaktionen der letzten 2 Stunden[cite: 7, 9]. Erlaubt das sofortige Gegenprüfen frisch diktierter Buchungen[cite: 7, 9]. Klick öffnet das Konto direkt im Arbeitsbereich[cite: 7].

3. Nahtloser Verlauf

Speichert die letzten 10 besuchten Kontexte (Assets, Berichte, Budget-Kategorien)[cite: 7, 9]. Klick stellt den Viewport und Zustand lückenlos wieder her[cite: 7].

Enterprise Troubleshooting & Fachglossar

❓ Browser verliert Dateizugriff nach Neustart

Sicherheitsrichtlinie der W3C File API: Nach dem Schliessen des Browsers muss die Projektdatei einmalig via Datei ➔ Öffnen bestätigt werden. Der Pfad bleibt im Recent-Cache erhalten.

❓ Ticker-Kürzel für SIX Swiss Exchange

Schweizer Titel benötigen bei EODHD das Suffix .SW (z.B. NESN.SW für Nestlé, NOVN.SW für Novartis, VWRL.SW für Vanguard FTSE All-World). US-Titel enden auf .US (z.B. AAPL.US).

❓ Mikrofonzugriff unter Windows für Copilot-Diktat

In Windows 10/11 unter Einstellungen ➔ Datenschutz & Sicherheit ➔ Mikrofon den Schalter „Desktop-Apps den Zugriff auf das Mikrofon erlauben“ aktivieren.
